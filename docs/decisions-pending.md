# 待决定事项

迭代需求时遇到、需要项目负责人拍板的问题。决定后在对应条目写明结论，再按结论实现。

## 已决定（2026-10-17）

- AdGuard Home：默认安装，并作为路由器的默认 DNS。
- 多 WAN：不做负载均衡；做出口检测与故障切换（按优先级，有线 > 中继 > 手机共享/上网卡，IPv4 和 IPv6 一起，切换时默认断开旧连接）。
- 远程访问：只做 Tailscale，不做 ZeroTier。
- 只支持 256MB 闪存的 TR3000，不再提供 128MB 版镜像。
- 无线国家/地区：默认 CN（出厂默认里设置）。
- 加密 DNS 默认服务商：阿里 DNS，`https://223.5.5.5/dns-query`（按 IP 访问，不依赖域名解析）。
- VPN：只提供客户端，不做 WireGuard/OpenVPN 服务端和 VPN 级联（已移除 WireGuard 服务端）。
- IPv6：默认开启；VPN 连接且配置里没有 IPv6 地址时阻止 IPv6 转发。
- 真机默认 LAN 地址：192.168.200.1。
- 首次开机：开启名为 SupaCudy 的无密码 Wi-Fi。
- 产品名：SupaCudy。
- 统一密码：SSH、网页界面、AdGuard Home 以及以后带登录的地方都用 root 和同一个管理密码（Wi-Fi、VPN 除外）。出厂登录为 root / supacudy。
- 默认打开 SupaCudy；侧边栏左下角提供跳转原生 OpenWrt 的入口，跳转前提示风险。
- 救援模式只在当次启动有效，不得改写用户的 Wi-Fi 和接口配置。
- 新增需求：参考 GL.iNet，路由器无法给设备分配地址时（例如接入点模式下主路由器消失）自动进入兜底状态，让用户仍能连上路由器进行配置，并用指示灯提示。

## 功能取舍

1. **AdGuard Home 是否打包进固件**
   - 体积：下载约 10 MB，安装后约 30 MB；128 MB 闪存的 TR3000 装得下，但会挤占 overlay。
   - 选项：A. 打包进固件；B. 不打包，在界面里提供"从官方源安装"（需要联网）；C. 不做。
   - 倾向：B。

2. **多 WAN 故障转移的做法**
   - 现状：有线 WAN（度量 0）→ 中继（20）→ 手机共享（30），链路断开时自动切换；但链路还在、上不了网时不会切换。
   - 选项：A. 引入 mwan3（需要调整它的 fwmark 掩码，避免和 VPN 分流用的 0x100 冲突）；B. 自己做轻量探测（定时 ping，失败时调高该出口的度量值）。
   - 倾向：B，依赖更少、行为更好控制。

3. **Tailscale、ZeroTier 是否提供**
   - Tailscale 安装后约 20 MB 以上，还需要用户有账号；ZeroTier 较小。
   - 选项：A. 两个都做；B. 只做 ZeroTier；C. 暂不做。

4. **IPv6 的默认策略**
   - 需要决定：默认是否开启；VPN 连接时 IPv6 怎么处理（直接阻止 IPv6 出站以防泄漏，还是要求 VPN 配置带 IPv6 地址才放行）。
   - 倾向：默认开启；VPN 连接且配置里没有 IPv6 地址时阻止 IPv6 转发。

5. **OpenVPN 服务端、VPN 级联**：使用场景少，是否继续做，还是从路线图移除。

6. **LED 定时、侧边拨动开关**：需要先在 TR3000 真机上确认有哪些 LED 和按键、它们在系统里的名字。

## 已知限制（不需要决定，记录在此）

- 浏览器会缓存 /supacudy/ 页面，升级后可能要强制刷新一次才能看到新界面（uhttpd 不发 Cache-Control）。
- 只让部分设备走 VPN 时，这些设备的 DNS 查询仍按路由器的 DNS 设置走；需要保密时请同时开启加密 DNS。
- 按网站分流：网站的地址在设备查询域名时才学到；修改要分流的网站列表时清空重学（同时清掉 AdGuard Home 的缓存，让下一次查询能到达 dnsmasq）。设备自己缓存的旧地址在它下次查询前仍走原线路。
- iPhone 的 USB 共享网络、硬件流量卸载、真实固件升级只能在真机上验证。
- 在 SupaCudy 之外（SSH 里的 passwd、LuCI）改了管理密码时，AdGuard Home 仍用旧密码，直到在“广告过滤”页输入一次新密码。
- 按设备分流 VPN 时，被选设备的 IPv6 一律不走隧道而是被阻止；按网站分流只对 IPv4 地址生效。
